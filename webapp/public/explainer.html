The three-step idea

step 1 — open

Commit + commit

Each player publishes (a) an identity commitment and (b) a Merkle root over their 81 one-time tokens.

step 2 — play

Reveal & verify

Each move reveals one secret. The opponent recomputes the leaf hash + Merkle path. Pure local computation.

step 3 — settle

One proof

A single settle circuit replays the whole history, verifies every token, records the winner.

The asymmetric trust: only the player who committed the root can produce valid tokens under it. That replaces the role of a digital signature — which Compact doesn't expose in-circuit (yet).

Identity = hash of a secret

No public keys. Each player picks a 32-byte secret skP and publishes only its hash.

skX = ↓ idX = persistentHash("ttt:id:", skX) =

To prove "I am X" inside a circuit, the caller supplies skX as a witness; the circuit recomputes the hash and checks it equals the registered idX. Unforgeable, non-transferable.

Per-move auth: one-time tokens

For every reachable (turn, cell) the player generates a fresh secret. 9 turns × 9 cells = 81 leaves.

81 secrets (turn × cell)

Merkle root (depth 10)

Only the root goes on chain. The 81 secrets stay in the player's browser. Revealing one is what "plays" a move.

A leaf per (turn, cell)

Each leaf is bound to both its turn and its cell. That's what makes one secret authorise one move — and nothing else.

81 real slots + 943 zero-padding slots = 1024 leaves (depth-10 tree). The padding exists because a Merkle tree must be a power of 2; the player never uses it.

Who puts the commitments on chain?

If one player deploys with both sides' commitments, they could substitute fake ones for the opponent. So we split the open into two transactions — each player submits their own.

phase 1
X  calls  deploy(idX, rootX)  → contract state:  halfOpen
idO & rootO are still zero. No settle, no fraud proof, no timeout can be called yet.
phase 2
O  calls  joinChannel(idO, rootO)  from their own browser  → status flips to  inProgress
The idO & rootO on chain are now provably the values O submitted. The game can begin.
Front-run mitigation. If a malicious X tries to call joinChannel themselves with fake O-credentials, status flips to inProgress before O can join. O's later joinChannel tx will revert (“channel already open”) — an explicit on-chain signal that the contract was tampered with. O walks away having revealed nothing.

Settle: one transaction, the whole game

The 5 moves compress into a single ZK proof. The contract verifies every token in one circuit pass.

callTx.settle( 5, // nMoves [0, 3, 1, 4, 2, …], // cells [s[0][0], s[1][3], …], // secrets (one per turn) [path[0][0], path[1][3], …], // Merkle paths challengeUntil )
The proof internally checks every token's Merkle path against the players' published roots. Cheap settlement amortised across all moves.

Cheating? Instant loss.

A token authenticates exactly one (turn, cell). Reveal two for the same turn — you've handed the opponent a slashing proof.

X plays turn 2 — twice

…even across time

A backtrack looks different to humans. To the contract it's still same turn, two cells — the exact same fraud proof flies.

P2's local log

P2 stores every incoming SignedMove keyed by turn. When a second turn-0 message arrives, the new token is captured even though the move is rejected as out-of-order.

The contract sees the tokens, not the timing. Concurrent fork, retroactive rewind, decade-late leak — same proof, same outcome. One primitive handles every shape of fork.

Silence? Forfeit.

Opponent stops responding. The waiting player arms an on-chain timer; expiry = forfeit.
